## 1. `scripts/20_parse_rad.py` → `rad.json`

### 쓴 자료와 문서

### 문서와 자료에서 확인한 것
| 항목 | 확인 결과 |
|---|---|
| LMST(화성 현지 평균 태양시) 형식 | 관측 머리말 `START_OBS_MARS="4710 0:52:55"` = `sol 시:분:초`. 관측 시작 시각이며 관측이 약 15분이라 시작 시각의 시(hour)에 넣었다 |
| QC 비트 의미 | **(정정, 6단계 검수) SIS 4.2.1.2절에 코드 표가 있다**: `00000000` 품질 문제 없음, `00000001` 알 수 없는 품질 문제가 있을 수 있음, `00000100` DAN 모드, `00001000` Solar Event 모드. 다만 같은 문단이 "QC와 로버 위치는 아직 구현되지 않은 자리 표시"라고도 적었다. 아래 원래 문장의 "문서에 없음"은 틀렸다. 원문: 문서에 없음. SIS가 "QC와 로버 위치는 아직 구현되지 않은 자리 표시"라고 적었다. 실제 값은 `00000000`과 `00000001`뿐이다(sol 4710–4843: 644건). 0이 아니면 모두 제외한다. 비트 의미는 모름 |
| B 대 E | 선량계 B는 실리콘(두께 300µm), E는 플라스틱 섬광체(조직과 비슷한 물질). 단위는 둘 다 µGy/h (파일 내 `UNIT`) |
| LET 히스토그램 | 52칸. 행 3개(칸 중심, 칸 너비, 값). 중심 0.167–290.1 keV/µm. 값은 관측당 개수를 가동 시간 비율로 나눈 것이다(예: 2.062 = 2/0.9697, 같은 관측의 L1 카운터 가동률 96.97%). 시간당·LET당 값이 아니다. 기간 전체 합산은 "상대 분포"로만 쓰고, 칸 너비로 나눠야 LET당 밀도가 된다. SIS는 "keV/µm로 환산된 에너지 칸"이라고만 적었고 정규화는 쓰지 않았다. 위 해석은 자료의 숫자에서 직접 확인한 것이다 |
| 로버 위치 | `ROVER_LAT/LON/ELEV`는 전 관측 0이다(자리 표시) |
| 선량 값이 있는 관측 | 관측의 절반(홀수 번호)은 PHA만 있고 선량이 없다 |
| 초기(sol 0–359) 파일 형식 | `OBS_DURATION`이 없고 QC에 따옴표가 없다. 관측 시간은 L1 카운터의 가동 시간 ÷ 가동률로 계산했다(최근 형식에서 이 방법은 `OBS_DURATION`과 ±1초 안에서 일치: 예 931/0.9697=960 대 961) |

- 관측 단위 기울기: E가 기압 1Pa 상승당 약 -0.0196%(기압 640–885Pa 범위). 대략 기압이 100Pa 오르면 E가 약 2% 낮다는 크기이다.
