# 15. 5-5단계 A부 소매 체크리스트 결과

용어
- 소매 체크리스트(cuff checklist): 우주복 소매에 차는 작은 수첩. 여기서는 종이 카드 묶음.

- †: 가정 표시. 카드에도 "† = 가정"이라고 적었다.

### 1-1. 계산은 EVA 모드와 같은 코드

`cards.js`는 새 계산을 하지 않는다. 가져다 쓴 것은 다음과 같다.

| 값 | 출처 |
|---|---|
| 설정(P) | `state.makeParams` (주소 읽는 규칙은 `eva.js`의 `readSettings`와 같음) |
| 한도 네 개, 걸린 조건, D, 복귀 기한, 여유, 되돌아갈 지점, 최대 체류, 총 시간 | `state.evaPlan` |
| 지점별 도착 시각, "늦어도 돌아설 시각" L_k | `evaPlan().stations[k].arrive_s`, `.L_s` |
| 도착 시각의 선량, 지면 온도 | `state.doseAt`, `state.groundAt` |
| LMST | `state.lmstAt` |
| 왕복 거리 | `state.tripTotals` (계획 패널과 같은 `summary`) |
| 방위 | `routecalc.bearingDeg` (EVA의 "다음 지점"과 같은 함수) |
| 구간 거리, 오르내림, 최대 경사, 15°/25° 이상 길이, 가시권 밖 길이 | `routes.json`의 `stations[].leg` |
| 한도 이름, 선량 측정 장소 문구 | `eva.*.json`을 읽기 전용으로 사용 |

`cuff.js`에는 글자 모양을 만드는 작은 함수(T+, LMST, 방위 8방위)만 있다. 값은 새로 만들지 않는다.

### 1-2. 주소 매개변수 (13 문서 2절)

`route=A|B`(기본 B), `start`(LMST 시, 기본 10), `season`(옛 `ls=`도 받음), `lang=en|ko`, `scenario`(`spike4716`은 경로 B만), `pace`, `stay`, `auto=0`. 엉뚱한 값은 EVA 화면과 같은 기본값으로 돌아간다. 화면에서 언어를 바꾸면 주소가 갱신된다. "EVA 모드 열기" 링크는 같은 설정을 `eva.html`로 넘긴다.

## 2. 카드 목록

카드 크기 90 × 60 mm와 A4 한 쪽 8장은 **가정**이다. 실제 소매 체크리스트의 크기는 확인하지 않았다. 화면 위쪽 안내와 요약 카드에 "가정"이라고 적었다.

| 순서 | 카드 | 내용 |
|---|---|---|
| 1 | 요약 | 경로 이름, 왕복 거리, 계획 EVA 시간(보행 시간), 출발 LMST, 계절 Ls, 유효 한도 D†(걸린 조건과 T+, LMST), 기지 복귀 기한과 여유†, 되돌아갈 지점(목적지 도달 가능·최대 체류 / 되돌아갈 거리 / 출발하지 않음), 선량 출처 기간, 보행 속도†, 자기 나침반 불가 한 줄, 만든 날짜, "카드 크기 가정" |
| 2–N | 지점 카드(지점마다 1) | 번호(k/전체)·종류, 이름, 좌표·고도, 다음 지점 방위·거리(큰 글자), 구간 시간·오르내림, 돌아갈 때 방위·거리, 경사 경고, 가시권 경고, 도착 T+·LMST, **늦어도 돌아설 시각**(굵은 상자), 지면 온도, 도착 시각의 선량 E / Si |
| N+1 | 한도 표 | 시간·일몰·지면 온도·선량 네 한도(T+, LMST, 걸린 조건은 ►와 굵은 테두리), 지점별 돌아설 시각과 도착 시각 표 2단 |
| N+2 | 돌발 상황 | 25° 이상 경사, 가시권 상실, 선량률 경보 때 한 줄씩(가정이라고 †), 한계 문구 요약 |

모든 카드 머리에 `시뮬레이션 · 경로 B`가 들어가 낱장으로 떨어져도 표시가 남는다.

### 2-1. 경고 표시 (색 없이)

| 상황 | 표시 |
|---|---|
| 경사 15° 이상 | `▲` + 상자 테두리 + 글자 "최대 17° · 15° 이상 8 m" |
| 경사 25° 이상 | `■` + 상자 테두리 |
| 다음 구간 가시권 밖 | `▲` + 상자 |
| 되돌아갈 지점 | `■` + 상자 + 방위·거리. 되돌아갈 지점이 두 지점 사이에 있을 때 앞 지점 카드에 넣는다(EVA 화면이 "TURN POINT"를 다음 목적지로 보여 주는 것과 같게) |
| 되돌아갈 지점보다 먼 지점 | 카드 테두리 이중선 + `■` 문구 |
| 걸린 한도 | `►` + 굵은 테두리 |

카드는 흰 바탕·검은 글자만 쓴다(점검에서 사용된 색이 `rgb(0,0,0)`, `rgb(255,255,255)` 둘뿐임을 확인).

### 2-2. 글자 크기

모든 글자 9pt 이상. 방위·거리 14pt, "늦어도 돌아설 시각" 값 14pt, 복귀 기한 등 11pt(09 문서 8-2절의 14pt 이상 목표 중 방위·거리·돌아설 시각을 충족).

## 3. 인쇄 규칙

- `@page { size: A4 portrait; margin: 10mm }`.
- 카드는 90 × 60mm, 한 장(`.sheet`)에 2열 × 4행 8장. 쪽 폭 190mm 안에 180mm, 높이 277mm 안에 240mm가 들어간다.
- 카드를 8장씩 `.sheet`로 묶고 `break-after: page`로 나눈다. 카드마다 `break-inside: avoid`. 마지막 `.sheet`는 쪽 나눔 없음(빈 쪽이 생기지 않는다).
- 자르는 선은 카드 테두리(0.25mm 실선).
- 화면에서는 같은 배열을 종이 모양으로 미리 보여 주고, 위에 "인쇄 / PDF 저장" 단추, 언어 단추, EVA·계획 링크, 현재 설정, 카드 수, 가정 안내를 둔다. 인쇄 때 이 영역은 `display: none`.

### 4-3. 방위 손계산 (`python3 -I`)

## 6. 알려진 한계

1. 카드 크기 90 × 60mm와 한 쪽 8장은 가정이다. 실물 소매 체크리스트의 크기는 확인하지 않았다.
2. 한도 값(6시간, 여유 30분, 일몰 17.5시, −40°C, 선량 예산 50µGy)은 모두 가정이다. 선량 예산은 계획용이고 보건 기준이 아니다. sol 4716은 "돌발 사건, 원인 미확인"으로만 적었다. 돌발 상황 카드의 행동 한 줄씩도 이 시연용으로 가정한 일반 수칙이며 비행 절차가 아니다.
3. 카드의 선량과 지면 온도는 도착 예정 시각의 값이다. 늦게 도착하면 달라진다. 되돌아갈 지점 너머 지점의 값은 "그곳까지 계속 걸었다면"의 값이고 `■`로 표시된다.
4. 한도 표 두 단이 지점 11개까지 들어가게 했다. 지점이 12개를 넘으면 표가 칸을 넘칠 수 있다(경로 A·B 모두 지금은 문제 없음). 이름이 아주 긴 지점은 머리줄이 두 줄이 될 수 있다. 점검은 넘침을 잡는다.
5. 한국어 PDF 글꼴은 Chrome이 시스템 글꼴로 고른 것이다. 다른 기기에서 인쇄하면 글자 폭이 달라질 수 있다.
6. 확인한 브라우저는 Chrome(헤드리스)뿐이다. Safari 인쇄(09 문서 10절 11번), 흑백 프린터로 실제 인쇄, 실제 종이 크기는 확인하지 않았다. PDF 쪽 검사는 `pdftotext`의 글자 위치 기준이다.
7. 요약 카드의 "만든 날짜"는 페이지를 연 날의 날짜다. 자료 기간은 선량 줄에 sol 범위로 넣었다.
8. 오프라인 동작(`cuff.html`의 서비스 워커 저장)은 이 작업의 범위 밖이다. `cuff.html`에는 `src/sw-register.js`를 불러오는 줄만 넣었다.
