# 18. 웹사이트 구성 계획

2026-11-15. 계획만 적는다. 이 문서를 쓰면서 `site/`와 `scripts/`는 고치지 않았다.
지금 `site/`는 화면 세 개(계획 지도, EVA 재생, 소매 체크리스트)뿐이다. 여기에 소개·방법·출처·전자부품 페이지를 더해 하나의 프로젝트 웹사이트로 만든다. 배포는 GitHub Pages 하위 경로(예: `/marswalk-gale/`)다.

읽은 것: Plan 00, 02, 06, 07, 08, 09, 10, 11, 12–16, `site/*.html`, `site/sw.js`, `site/src/main.js`, `i18n.js`, `eva/ei18n.js`, `scripts/54–59`의 주소 사용처, `site/data/rad.json`·`config.json`.
Plan/17(6단계 검수)은 아직 없어서 읽지 못했다. 17에서 P1(먼저 고칠 것)이 나오면 5절 순서를 따른다.

용어
- 랜딩 페이지: 사이트 주소를 처음 열었을 때 보이는 소개 페이지.
- 앱 뼈대(shell): 서비스 워커가 첫 방문 때 저장하는 HTML·JS·CSS·문구 파일 묶음(16 문서).
- 사실 파일: 소개 페이지에 쓰는 숫자를 한곳에 모은 작은 JSON(이 계획에서 새로 만든다).

## 0. 결론

1. 최상위 주소(`index.html`)는 새 홈(소개)으로 쓰고, 지도는 `map.html`로 옮긴다.
2. 새 페이지는 4개: 홈, 방법(`about.html`), 전자부품 영향(`electronics.html`), 자료 출처(`sources.html`).
3. 숫자는 페이지에 직접 적지 않는다. `site/data/*.json`에서 뽑은 사실 파일로 채우고, 점검 스크립트가 다시 계산해 대조한다.
4. 프레임워크·빌드·패키지 설치 없음. 기존 `app.css` 색 토큰과 `i18n.js`를 그대로 쓴다.
5. 구현은 6단계 P1 수정이 끝나고 점검 54–59가 통과한 뒤에 시작한다. 에이전트 작업 시간 약 11–13시간(추정).

### 2-5. 자료 출처 (`sources.html`)

- 표 한 개: 미션·기기 / 제품 이름·ID / 원본 주소 / 라이선스·표기 문구 / 받은 날짜 / 이 사이트에서 쓴 곳.
- 원본: `Geology/`, `Photos/`, `Vector/`, `Reference/`, `Radiation/pds/`의 `SOURCES*.md`(읽기만)와 08 문서 "NASA data used". 이를 `site/data/sources.json`으로 옮긴다.
- 라이선스나 저자가 확인되지 않은 항목(예: Rudolph 지질 자료, 12 문서 6절)은 "확인 필요"로 적는다. 지어내지 않는다.
- Leaflet(BSD-2)과 AI 사용 고지도 여기에 둔다.

### 2-6. 두 언어

- 방식은 EVA·체크리스트와 같다. HTML 본문은 영어, `data-s="키"` 자리를 사전으로 바꾼다. 언어 선택(`?lang=`, localStorage `gale.lang`)은 공통 `i18n.js`가 맡는다.
- 사전은 페이지별로 나눈다: `src/i18n/site.{en,ko}.json`(공통 메뉴·바닥글), `home.*`, `about.*`, `elec.*`, `sources.*`. 여러 에이전트가 같은 파일을 고치지 않게 하기 위해서다.
- 영어와 한국어 사전의 키 구조가 같은지 점검한다(기존 점검과 같은 방식).
- `i18n.js`는 문서 제목을 `ui.doc_title`로 덮어쓴다. 새 페이지는 `ei18n.js`처럼 자기 사전의 `doc_title`로 다시 정한다.
