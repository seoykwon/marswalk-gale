How Ls is computed

Solar longitude (Ls) gives the season of each sol. The REMS archive files carry no Ls, so it is computed with Mars24 (Allison & McEwen 2000) from the REMS timestamp of each sol, evaluated at local noon (scripts/ls_mars24.py). The code reproduces both worked examples published with Mars24 and gives 150.7° at the Curiosity landing, matching the published value. An outreach file from Centro de Astrobiología (CAB) was used only as a cross-check; its provider discourages other uses. Algorithm: Mars24. Allison, M., and M. McEwen (2000), Planet. Space Sci., 48, 215–235, doi:10.1016/S0032-0633(99)00092-6. See entry LS.

Use of AI tools (Super Intelligence, SI, in Space Apps terms)

Marswalk was built with Claude Code, an AI coding assistant from Anthropic. The planning was done with Claude Fable 5.2. The implementation was done with Claude Opus 5.5 and Claude Sonnet. Claude Code wrote and edited the project's source code (the web pages under site/ and the data-processing scripts under scripts/), wrote the planning and review notes, and drafted the text of the interface and of this documentation. The data processing and the checks were run by those scripts, not by the assistant by hand: the scripts read the NASA and USGS source files listed above and produced the map tiles, route profiles and numbers shown on the site. The numbers shown on the site come from those source files and scripts; the assistant did not supply measurements. The project owner chose the challenge, came up with the idea, set the scope and made the decisions, and reviewed the output. Assumptions that are not from NASA data (for example antenna height and slope hazard classes) are labelled as assumptions. No images, video or audio on the site were generated by AI. Images on the site are NASA mission data or screenshots of the app itself. No generated content uses NASA logos, flags or mission identifiers.
